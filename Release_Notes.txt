* V2.1.0_R0.0_M0.0.0.0 *
----------------------------
Feature(EN):
    * Added board types mrs6241_p2828 and mrs6241_p2840;
    * Added a radar framework to unify the codebase for most radar projects;
    * The radar_analysis project now supports mrs6241_p2828 and mrs6241_p2840;
    * Added radar projects: ReportDataCube1D, ReportDataCube2D, Posture, Sleep, and Tracking;
    * Added Host projects: burn_sample, cmd_and_report_sample, hif_port_host_sample, multi_buff_sample, and multi_device_sample;
    * Added Device projects: hif_spi, hif_uart, hif_i2c, hif_split, hif_port_device_sample, and hif_port_device_time_meas;
    * Removed radar projects: factory_test, mmw_point_cloud, and r3_databox;
    * Removed projects: r3_databox_host and RadarDebugTool_sample;
    * Added system keep-alive mechanism, including heartbeat reporting, response count reporting, watchdog, and looptask monitor
      for supervising radar operation status;
    * Added support for 64M 4-line SPI;
    * SPI 64M 1-line 2DFFT supports 256KB at 10Hz;
    * SPI 64M 1-line 2DFFT supports 64KB at 50Hz;
    * SPI 64M 1-line 1DFFT supports 8KB at 200Hz;
    * HIF supports a timeout mechanism, releasing memory if not read within the timeout;
    * HIF supports caching multiple frames to reduce the real-time requirements of the Linux system;
    * HostDriver supports multiple slaves, including multiple slaves on different buses and multiple slaves on the same bus;
    * HIF supports defining proprietary protocols;
    * HostDriver supports parsing proprietary protocols;
    * Added temperature-triggered calibration, triggered when temperature change exceeds 20°C;
    * Moving point cloud supports up to 768 points;
    * Support ADC, 1DFFT, 2DFFT, point cloud, micro-motion point cloud, and presence point cloud reporting;
    * Added support for obtaining Interval 0 range FFT data when performing 2D-FFT in 2D frame mode;
    * Added interfaces for configuring and retrieving radar calibration values;
    * Added an interface for retrieving the frame start timestamp;
    * Refactored the factory test function, streamlined the factory test API, improved ease of use, and maintained compatibility with
      the existing factory test process.

Perf(EN):
    * Improved bootloader firmware loading speed;
    * Optimized HIF architecture to improve data reliability (retransmission) and ease of use for large data transfers
      (fragmentation);
    * Optimized HostDriver architecture to improve data reliability (retransmission) and ease of use for large data
      transfers (fragmentation);
    * Optimized the presence detection algorithm, improving detection performance and reducing the false alarm rate;
    * Refined memory usage of each module to free up more idle SRAM space.

Fix(EN):
    * Fixed the issue where, when reporting data via MSG ID C6, if the HIF message length exceeds 4 KB, the bridge chip may
      interrupt reporting for 0.5 s, eventually causing radar memory overflow;
    * Fixed the issue where UART 2M/4M transmission has a high bit error rate;
    * Fixed the issue where thread creation hangs with extremely low probability;
    * Fixed the issue where MRS6240_P2512 cannot be soft-rebooted;
    * Fixed the issue where MISO is pulled low and stuck when using multiple SPI slaves;
    * Fixed the issue where the actual frequency is not 112 MHz when 6130 is configured to 112 MHz;
    * Fixed the issue where SPI configuration is incorrect after sleep/wake-up;
    * Fixed the issue where OSI_MSleep cannot sleep indefinitely;
    * Fixed the issue where the board_BlkDelay function has inaccurate delay timing;
    * Fixed the issue where the UART FIFO watermark interrupt cannot be configured;
    * Fixed the issue where triggering an interrupt during system scheduling may cause a hang with an extremely low probability;
    * Fixed the issue where 6240 cannot boot after enabling DCXO;
    * Fixed the issue where the watchdog cannot be used on 6240;
    * Fixed the issue where adaptive gain is incorrect when Doppler FFT is not enabled.

Change Log:
Feature(EN):
  Radar:
    * Newly defined user coordinate system: 
        - All development boards have the USB port facing down (side-mounted vertically) 
		  and the USB port facing right (side-mounted horizontally);
        - The target coordinates output by RadarAnalysisTool, point cloud, and r3_databox 
		  are all under the user coordinate system.
    * Newly defined radar coordinate system to ensure that the radar coordinate systems 
	  of RS6130 and RS6240 have similar antenna arrangements. Please refer to the 
	  <RS6x_7x_r3_PointCloud_Demo_User_Manual>.
    * The RadarAnalysisTool project newly supports RS6130 micro-motion point cloud.
    * The point cloud project supports micro-motion point cloud calculation and reporting.
    * The r3_databox project newly adds micro-motion point cloud, DataCube reporting 
	  (disabled by default), and caches and reports Range-FFT data when executing the 
	  2D-FFT process (disabled by default).
    * Support for switching between different CFAR algorithms is available in RadarAnalysisTool 
	  point cloud and r3_databox project.
      - The standard CA-CFAR has a relatively low point cloud density and is suitable for 
	    use indoors or on mobile platforms.
      - The signal-to-noise ratio threshold method has a relatively high point cloud density 
	    and is suitable for use in outdoor environments with sparse targets.
    * RadarAnalysisTool supports configuring whether to enable micro-motion point cloud.
    * Optimized HIF interface transmission efficiency.
    * The maximum DataCube can support 10Hz reporting.
    * The point cloud can support 20Hz reporting.
    * Use the memory management functions provided by the OS instead of C library functions 
	  in the point cloud algorithm.
    * The mmw_point_cloud_process() function no longer actively calls the function to restore 
	  adaptive gain; users need to manually call it at the end of the callback function.
    * For all radar samples, calculate the moving point cloud first, then the micro-motion 
	  point cloud to increase the upper limit of the frame rate.
    * Renamed the cosValue_Y member of the MmwAngleInfo_t structure to sinValue_Y to conform 
	  to physical logic.
    * Improved the comments in the r3_databox project and fixed the comment errors.
  Driver:
    * Added UART sleep and wake-up functions.

    * Fixed the header file configured in the point cloud project. The error in the 
	  configuration controlled by the MRS6130-P1806 macro caused the point cloud project of 
	  MRS6130-P1806 to use the same serial port for printing and HIF.
